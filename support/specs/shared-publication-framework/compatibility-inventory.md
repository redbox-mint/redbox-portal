## Figshare

`src/` paths here are relative to `packages/redbox-core/`.

- Public shim methods in `src/services/FigshareService.ts`: `createUpdateFigshareArticle`, `uploadFilesToFigshareArticle`, `deleteFilesFromRedbox`, `deleteFilesFromRedboxTrigger`, `publishAfterUploadFilesJob`, `queueDeleteFiles`, `queuePublishAfterUploadFiles`, `transitionRecordWorkflowFromFigshareArticlePropertiesJob`, `preparePublication`, `syncMetadata`, `syncAssets`, `syncEmbargo`, `publishIfNeeded`, `writeBack`, `syncRecordWithFigshare`, `init`, `validateFigshareRecord`, `wakeFigshareRecord`, `requestFigshareCleanup`, `dispatchSyncJob`, `syncRecordJob`.
- Additional subclass seams: `getConfig`, `getSyncState`, `setSyncState`, `validateHandlebarsTemplate`, `buildMetadataPayload`, `makeClient`. Worker execution must retain actual overridden payloads, client context and hashes. Registration uses `registerRedboxServices()` and the generated service shim; no direct edit to `api/services` is appropriate.
- `src/services/figshare-v2/source-intent.ts` discovers record type `onCreate`, `onUpdate` and workflow hook chains. Stable policy IDs, optional explicit IDs and execution conditions currently authorize **eligible saves**, not immutable approved snapshots. `RecordsService` prepares/finalizes protected intents and `RecordWriteOptions` carries internal save intent. Current stale-initialising recovery is baseline behavior, **not** certification of PUB-06's stricter successful-save contract.
- `src/config/agendaQueue.config.ts` registers `Figshare-SyncRecord`, `Figshare-Dispatch`, `Figshare-PublishAfterUpload-Service`, `Figshare-UploadedFilesCleanup-Service`. Old user/article payloads must not become shared authorization or binding identity.
- `src/configmodels/FigsharePublishing.ts` owns per-brand connection, processing, impersonation, article, record paths, selection, authors, metadata, categories, assets/staging, embargo, queue, workflow and write-back. Shared initial durations preserve 5000/120000/20000/60000/120000/300000 ms (coalesce/lease/heartbeat/retry/observation/cleanup), five durable attempts. Connection transport retry remains separate.
- Existing outputs include `metadata.figshare_article_id`, `metadata.figshare_article_location`, `metadata.figshareStatus`, `metadata.figshareError`, `metadata.figshareSyncState`, configurable all-files-uploaded and extra-field targets. Attachment selection reads `metadata.dataLocations`; these inputs and output classifications must not be conflated.
- `src/services/figshare-v2/{identity,assets,metadata,publish,worker,sync-store}.ts` and `src/model/storage/FigshareSyncModel.ts` carry account/owner separation, create tokens, uncertain outcomes, publish generations/hashes, receipt-owned files, checksums, curation waits, exclusive namespace/article ownership and conditional projections. Do not flatten these into generic mandatory provider phases.
- Crosswalk references use `sourceVocabularyId`, `crosswalkId`, output mode and approved revisions. `FigshareVocabularyService`, `FigshareVocabulary*` models and the existing `value-binding-editor`/category mapping widgets remain stage 1 compatibility surfaces. Contributor bindings evaluate a contributor root with ambient brand context; metadata bindings evaluate a record root.

Executable baseline coverage: `test/services/FigshareService.test.ts`, `figshare-{bindings,categories,managed-assets,queued,vocabulary-config}.test.ts`, `figshare-v2/runtime.test.ts`; lifted save coverage lives in repository `test/integration/services/FigshareQueued.test.ts`; atomic storage coverage is in `packages/sails-hook-redbox-storage-mongo/test/integration/FigshareIntent.test.ts`. `support/figshare/VERIFICATION.md` is earlier delivery evidence for the queued Figshare work.

## Oni

- `src/services/OniService.ts` exports `exportDataset`, `init`, `getConfig`. `exportDataset(oid, record, options, user)` currently awaits crate build, repository write, optional ingestion and internal record persistence, then returns the updated record. Remote failure currently raises `RBValidationError` through a hook.
- Protected override seams: `createRepository`, `runPublishDataset`, `ingestDataset`. Creator lookup and actual requester/approver affect RO-Crate history; they are distinct identities. Local background persistence identity must not replace historical attribution.
- `src/configmodels/OniPublishing.ts` retains root collection, metadata/organization/IRI preferences, selection, write-back, named sites, storage, ingestion and mapping. Site selection uses `options.site` / `defaultSite`; do not choose a shared destination by object order.
- Output paths default to `metadata.citation_url`, `metadata.citation_doi`, `metadata.publication_error` (see the current config for exact deployed overrides). The DOI placeholder and clean/public URL rules remain provider-owned.
- `src/services/oni-v2/{crate,mapping}.ts` consumes the record, related data-record OID, creators/approver, organization, generated dates, vocabulary and graph-entity context. Logical attachment paths preserve selection/order. Context overrides and asynchronous JSONata are part of mapping compatibility.
- `repository.ts` and `flydriveOcflStore.ts` use the pinned OCFL wrapper with FS and S3 Flydrive paths. Baseline tests establish existing operations, not interrupted-commit read-back safety (PUB-10). `ingestion.ts` rebuilds structural/search indexes; readiness is repository evidence, not verified object visibility.

Executable baseline coverage: `test/services/OniService.test.ts`, `test/services/oni-v2/{crate,repository,flydriveOcflStore,ingestion}.test.ts`. Repository tests cover FS and S3-backed driver selection, stream/transaction writes and failure propagation without claiming a real remote S3 service was contacted.

## Golden artifact provenance

`packages/redbox-core/test/fixtures/publication/baseline.ts` is a fixed synthetic source/configuration, using distinct creator and institutional approver and selected/unselected attachments. `figshare-payload.json` was captured from unmodified `buildMetadataPayload`; it preserves escaped Handlebars output, asynchronous JSONata arrays, category mapping, numeric license and an explicitly empty custom field. `oni-crate.json` was captured from unmodified `buildOniRoCrate`, including the complete serialized graph, attachment plan and URL. Only the clock is fixed (`2026-02-03T04:05:06Z`); graph identities/values are not normalized away. The new baseline tests compare complete serialized artifacts, not a second mapping implementation. Existing executable receipt/identity/recovery and ingestion/return/error fixtures remain in the regression suites listed above.

## Intentional changes in subsequent tasks

Explicit approval will authorize one sealed source revision and fixed destinations; ongoing eligible-save behavior must become explicit auto-sync. Draft validation, all-destination explicit approval validation and per-destination auto-sync failure will have different boundaries. Oni will return the record after durable acceptance, without an immediate fabricated citation or synchronous remote failure. Status will distinguish same-provider destinations and current versus historical evidence. Shared workflow `any` preserves unfinished approved siblings; `all` retains disabled/archived members until explicit request revision/revocation. No such processing migration is activated in PUB-01–03.
