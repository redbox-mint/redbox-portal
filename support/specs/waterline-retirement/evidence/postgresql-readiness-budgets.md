## Proposed measurable budgets (not accepted measurements)

The user provisionally accepted these limits for `next` on 2026-10-20. Record each
comparison and any authorized replacement in the dated group validation; formal
operations approval remains required for official releases. Measure both backends on the **same topology**, engine/FCV, fixture volume, concurrency and warm/cold
state. Compare at least 1000 measured operations after 100 warmups and three repeats; record p50/p95/p99, throughput,
error/conflict counts and durable completion. Migration/startup tests use repeated fresh/restored snapshots rather than
replaying bodies in a loop. Do not equate infrastructure costs of a new replica set with an ORM latency regression;
report both costs separately.

Common proposed acceptance targets: p95 ≤ 1.20× baseline, throughput ≥ 0.90×, no new correctness/security errors,
resident memory ≤ 1.10×, and no increase in leaked/live pools after shutdown. Startup persistence overhead ≤ max(250ms,
10% baseline); **do not relax the existing 12-second startup deadline**. Report p99 tails and errors even when aggregate
thresholds pass; material regressions require owner disposition. None of these targets is an empirical P0 result.

Connection budget proposal: **zero additional driver pools per group/entity**; one application persistence pool per
compatible effective connection policy, with separate Db handles/private Prisma clients per datastore. Two incompatible
core/storage endpoints require two pools; routing must be explicit. No client per model or request. Agenda address
clients, connect-mongo store and app-scoped GridFS pools are separately inventoried in
[native owners](native-owners.json), not concealed within that budget. Measure baseline startup/steady/draining/closed
connections, monitoring sockets and configured maxPoolSize; finalize numerical total caps with operations on actual
deployment concurrency. Every owned client must be closed after its last user drains; borrowed managers are never closed
by a group. Existing Agenda/session/GridFS lifecycle gaps are P1/P10 work.
