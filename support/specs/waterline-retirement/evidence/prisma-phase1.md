# Prisma phase 1 — foundation and cache C

2026-10-22; implementation `b5c4f6aab` (foundation), `b95d8c009` (cache), based
on `40e72038d`. ARM64 / 2 CPUs / 12 GiB; Node **24.16.0**, npm **11.20.0**.
Commands were sequential with external timeouts. Only owned `wrpz1-*` Docker
resources were used; unrelated development containers were untouched.

`npm view prisma dist-tags --json` and `npm view @prisma/orm-mongo dist-tags
--json` confirmed latest pins **8.0.0-rc.24** and **8.0.0-rc.19**. Root/core locks
were generated by npm 11.20.0 with `install --ignore-scripts --strict-peer-deps
--no-audit --no-fund`. RC24's CLI depends on cli-engine 0.9.0 while its Composer
and ORM tooling still declare 0.7.0 peers. Exact scoped overrides align both
with **0.9.0**, and Composer's Effect with **4.0.5** for its current optional
platform peers. Application Effect stays 4.0.2. Initial strict-peer failures
preceded these successful installs; no peer checks were disabled. Lock changes
restore the Prisma graph and npm's resulting transitive placements/resolutions.

Both TypeScript schemas live under core's `src/persistence/prisma`: `contract.ts`
for `mongodb` (CacheEntry now; M/R/Q and later core models follow), separate
`storage-contract.ts` for `redboxStorage` (empty until S). Core owns repository
composition/lifecycle, avoiding a storage-hook generator or circular ownership.
Each schema has committed generated JSON/declarations, copied into dist. Build
emits offline; CI/Docker and prepack verify freshness before rebuilding. No
schema synchronization, marker collection, transaction or new index requirement.

`prismaDatabase` is the first-party runtime seam: one lazy client per logical
datastore, borrowing existing pools. The optional loaded-model datastore alias
binds that schema for the application's lifetime; later groups must use the same
binding. Shutdown drains accepted work, closes Prisma clients, then pools; failed
closes retain ownership for retry. Import/shim generation opens no connections.
Cache driver CRUD/configuration and its driver-only prerequisite fixture were
removed; existing other-group driver owners remain pending their own phases.

MongoDB was exclusively standalone
`mongo:9.0.4@sha256:dc28ed5a9d0fc616903c3f463bb1e53b92b49f441721b91926e87d90bf957ce8`.
The live cache fixture had 1536 MiB. It checks Waterline/Prisma read and update
directions, ObjectId/string timestamps/JSON/doubles, missing-field preservation,
duplicate-update partial failure, explicit Prisma index DDL and lifecycle.

RC19 notes for the next phases: `contractFromJson<Contract>` replaces the pilot's
`contractJson` client option. There is no transaction or arbitrary-command API,
and no methods named `$runCommandRaw`, `findRaw` or `aggregateRaw`; use the actual
supported `client.raw.collection(...).aggregate(...).build()` plus
`(await client.runtime()).query(plan)`, or the exported Prisma control APIs for
catalog/DDL. The only cache driver operation retained is the binary-version
`buildInfo` query, unsupported by those APIs. These are logged as **C-PG-01–04**;
transport ownership is **F-PG-01**. Quirks **C-01–07** cover preserved service,
JSON/timestamp/update semantics and natural predicate-write improvement.

Measured `/usr/bin/time -v npm --prefix packages/redbox-core run generate:prisma`:
**4.64 seconds**, maximum RSS **296,524 KiB (290 MiB)** for both schemas on ARM64.
This is a cache-plus-empty-storage measurement; remeasure as models grow. CLI
emits the existing harmless TypeScript module-reparse warning; no package-wide
ESM conversion is needed. All new raw/native exceptions must enter the rewrite
register. Add models, run `generate:prisma`, commit both generated pairs, and
reuse the same runtime client rather than creating per-group pools/clients.

Required-field nullable comparison typing is narrower than legacy queries; the
cache uses Prisma `MongoFieldFilter.eq` to preserve null comparisons without raw
CRUD. Optional JSON decodes missing values as null: keep physical absence on
patches and string timestamps, and add each new Mongo-specific use to the register.
