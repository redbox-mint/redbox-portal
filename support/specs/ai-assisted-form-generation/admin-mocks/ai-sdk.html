const openrouter = createOpenAICompatible({
  name: 'openrouter',
  baseURL: 'https://openrouter.ai/api/v1',
  apiKey: process.env.OPENROUTER_API_KEY, // env:OPENROUTER_API_KEY
  headers: { 'HTTP-Referer': 'https://redbox.example.edu.au', 'X-Title': 'ReDBox' },
  supportsStructuredOutputs: true,
  transformRequestBody: (body) => ({ ...body, stream: false,
    provider: { zdr: true, data_collection: 'deny', allow_fallbacks: true, sort: 'price', require_parameters: true } }),
});

await generateText({
  model: openrouter('anthropic/claude-haiku-4.5'),
  temperature: 0.2,
  maxOutputTokens: 4096,
  output: Output.object({ schema: /* built from the profile */, name: 'redbox_generation_candidate' }),
  providerOptions: { openrouter: { strictJsonSchema: true } },
  maxRetries: 0,
  telemetry: { isEnabled: false },
});

Design notes. This screen configures the Vercel AI SDK layer directly, using the SDK’s own vocabulary as secondary labels (apiKey, maxOutputTokens, providerOptions) so admins who know the SDK can map every field, while plain-language labels lead. It follows the long-form app-config pattern: rail, collapsible sections with one-line summaries, sticky save bar. Providers map to createOpenAICompatible() / createAmazonBedrock(); Models are named aliases (like the SDK’s customProvider/registry) so profiles reference rdmp-default, not a raw ID. Default settings are the generateText() call settings, with a support matrix because each adapter accepts a different subset. Hard-coded safety choices in the adapters (no streaming, tools, telemetry or redirects; SDK retries 0) are shown, not hidden, with reasons. “SDK code” renders the effective call so a technical reviewer can check exactly what will run. Stored as today: connections → GenerationModelConnection, models + settings → GenerationModelDeployment (parameters, routingPolicy).
