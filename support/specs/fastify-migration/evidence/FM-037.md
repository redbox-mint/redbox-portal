# FM-037 — Update generators and v6 scaffold

## Revision 2 — Review round 1

All five review findings are in scope. `config-helper.ts` now compares the complete
literal declaration for a method/path before accepting a rerun. A different
controller/action, access, CSRF or API source produces a clear conflict error;
method/controller preflight occurs before saving output. Regression tests exercise
both public→protected and protected→public and compare unchanged controller,
route and auth files. Production HTTP verifies the preserved public route and
protected route after those rejected CLI reruns.

Webservice declarations now include executable `api` metadata with the same
method/path/controller/action/CSRF and explicit policy names as the outer route.
Production API2 resolution normalizes that source and the host selects
`apiProtect`, exactly as it does for first-party APIs. Verified bearer mutations
need no session CSRF; cookie requests still need CSRF and canonical Origin.
Public webservice routes use the explicit unauthenticated `nocache` policy in
both the access declaration and executable API source: API metadata requires a
non-empty named policy array, and this policy introduces no auth requirement.
The generator also emits/exports `apiPolicies`, an explicit per-controller/action
`true` mapping for public API actions only. The deployment merges this after its
base `http.policyConfiguration` through the supported bootstrap input; API route
policies prepend rather than replace that source mapping. This is generated
application wiring, supplied alongside concrete factory inputs; no generated
source is patched. Other action mappings retain their base protection. The matrix
composes/exercises public webservice GET/POST alongside protected APIs using that
export. An exploratory combined-option run caught the inherited default mapping
(404 from missing brand context), and the final generator supplies the scoped
mapping required by the existing API2 contract. Denied declarations have no
executable API source. Webservice OPTIONS is rejected
explicitly because API declarations do not support it and the host owns OPTIONS.

`controller-factory.ts` follows the imported `defineController` (including an
import alias), exported factory, create expression, constructed class, input
interface, action list and declared identity through the AST. It does not assume
an export named `controller`, the first class, or identity equal to the filename.
Method additions preserve existing registration and bindings. This covers the
scaffold's `exampleController` / `ExampleFm037Controller` without registering it
twice. New controller registries/indexes also derive their exports from the AST.

`identifier.ts` supplies one shared spelling/validation function for the HTTP
generators (controller, method, Angular app). It converts word separators to camel
case, rejects invalid class keywords and prototype/input names, and is used for action
and class symbols. Angular `review-app --ejs-view review-view` emits
`ReviewAppPageController.adminReviewView`, its typed renderer input, factory,
registration and route. The action delegates to an explicit application-owned
`render(request, reply, view, title)` operation. The production test binds that
operation to public `prepareNativePage`, `renderPageShell` and `sendPageResponse`
with the normal session CSRF operation; the real shared EJS tree renders over HTTP.
Keeping the rendering operation in the application also prevents the source-linked
test host and installed compiled extension from loading separate request-context
WeakMaps. No generated output is patched to change transport behavior.
The former Angular-placeholder deferral is withdrawn.

import type { FastifyRequest, FastifyReply } from 'fastify';
import { defineController } from '@researchdatabox/redbox-core/http';

export interface ProbeInput {
  /** Supply the selected application operation; constructors acquire no resources. */
  read(request: FastifyRequest): Promise<unknown>;
  write(request: FastifyRequest): Promise<unknown>;
  added(request: import('fastify').FastifyRequest): Promise<unknown>;
}

export class Probe {
  public constructor(private readonly input: ProbeInput) {}

  public async read(request: FastifyRequest, reply: FastifyReply): Promise<unknown> {
    // Read the live request after hooks; typed failures reach the host's safe error boundary.
    const result = await this.input.read(request);
    return reply.type('application/json; charset=utf-8').send(JSON.stringify(result));
  }

  public async write(request: FastifyRequest, reply: FastifyReply): Promise<unknown> {
    // Read the live request after hooks; typed failures reach the host's safe error boundary.
    const result = await this.input.write(request);
    return reply.type('application/json; charset=utf-8').send(JSON.stringify(result));
  }

  public async added(
    request: import('fastify').FastifyRequest,
    reply: import('fastify').FastifyReply
  ): Promise<unknown> {
    const result = await this.input.added(request);
    return reply.type('application/json; charset=utf-8').send(JSON.stringify(result));
  }
}

export const controller = defineController({
  name: 'ProbeController',
  actions: ['read', 'write', 'added'],
  create: (input: ProbeInput) => new Probe(input),
});
