### Accepted rule: a complete response survives post-EOF disposal failure

The user explicitly decided that once the **source emits EOF**, every byte has
been produced. A subsequent finaliser/cursor-close failure is a resource-cleanup
failure: the completed response remains 200. It must not be replaced, aborted or
held open for disposal. Retained Express also completes the response in this case;
Express remains unchanged.

The single Fastify `sendReadStream` helper now separates EOF/output completion
from source disposal. Standard `source.pipe(output)` retains backpressure and
ends output at EOF, independently of asynchronous source `_destroy`. Unlike
`pipeline(source, output)`, it cannot propagate a later source finaliser error
back into the already complete representation. Both source and output have
`finished(..., { cleanup: true })` observers, each with an immediate rejection
handler. Their joined work is awaited before releasing request ownership or the
owned-stream allowlist, even when one observation fails. Neither response
completion nor the first disposal failure short-circuits that join.

A source failure after EOF submits **one** `HTTP_STREAM_DISPOSAL_FAILED` diagnostic
through the existing redacting HTTP logger, inside the retained request lifetime.
It does not escape to the action's response-failure catch or an unhandled rejection.
The logger allowlists that fixed code, preserves a query-free path and a bounded,
non-coerced request ID, and discards the raw exception/message, query, credentials
and body. The production owner sink forwards the sanitized correlation record as JSON through
its existing string-only warning port;
uncorrelated diagnostics retain their preceding fixed-string output. Existing
sink-failure containment, degradation, accepted asynchronous log work and drain
rules are unchanged; no alternate logger or retry path is introduced.

All **pre-EOF** behavior stays qualified: safe pre-first-byte 500 for GET and HEAD,
HEAD consuming the same source with GET headers and no body, postcommit/pre-EOF
connection abort, empty export, client abort and session/onSend replacement.
Pre-EOF failures cancel both ends; late failures preserve the completed output.
Close still waits for disposal settlement, successful or failed, before releasing
borrowed Mongo pools. `pilot-pattern.md` records this explicit EOF rule beside
`ACCEPTED-EXPORT-PRECOMMIT-FAILURE`; the round-5 native safe-500 deviation remains.
