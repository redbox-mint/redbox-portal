## Implementation and review boundaries

- `src/extensions/contract.ts`: adds public `RedboxExtensionV2`, retaining existing
  non-HTTP field types. API1 declarations remain available for production Express.
- `src/extensions/loading.ts`: factors out the existing native CommonJS/ESM import
  and awaited registration inspection. The API1 loader delegates to that same
  implementation with unchanged validation, provider ordering and error behavior.
- `src/extensions/v2.ts` and `index.ts`: export API2 installed-provider loading and
  complete offline composition. Reject API1, mixed legacy HTTP fields and raw
  server integrations with provider identity, the constructs found, expected API2,
  concrete conversion guidance and a link to [migration instructions](../extension-api2.md).
- Non-HTTP contributions pass through the existing resolver; only data is projected
  into its common validation/selection path. No HTTP handler is interpreted or
  adapted. Module/work prerequisites, cycles, named replacements, core-lowest and
  first-listed-highest precedence, deterministic unlisted order and package-relative
  views/assets retain their existing behavior and original declaration references.
- API2 controllers and routes feed the existing FM-009/FM-010 composers. Unknown or
  missing bindings, changed action exposure, missing replacement targets, unknown
  policies and undeclared route overlaps fail before construction. API declarations
  retain their executable schemas, response metadata and normalized effective policy
  chain, including effects before `false`. Existing extension route names remain
  unchanged. API2 public access is `{ kind: 'public' }`; empty policy lists cannot
  grant public access. Existing API policy configuration retains explicit `true`.
- Controller substitution changes implementation only. Controller instance fields
  do not become route access/CSRF/API metadata. Factory descriptors cannot carry
  route metadata. Access/schema/CSRF changes require a complete named route
  declaration with `replaces: true`. Offline `routePlan.routes` retains the selected
  route and its `replaced` history, including old/new effective policies, CSRF and
  executable API schema references. Validation stays at the explicit FM-016 action
  prelude position, after required policies and CSRF.
- Installed CJS/ESM and API1 HTTP packages are real files under
  `test/extensions/fixtures/api2-commonjs`, `api2-esm` and `api1-http`. Tests install
  them into disposable package directories, exercise public exports and real native
  import conditions, top-level await, default exports and async registration.
  One extension contributes a core controller subclass and the other a new
  controller with different concrete dependencies. Public author type fixtures
  compile both and reject API1 versions/Express handlers in API2 declarations.

Inspection instrumentation blocks Mongo client connect, TCP connect/listen, TLS
connect, explicit callback/promise file opens, read/write streams and filesystem
watchers. Source/manifest reads remain necessary for package inspection; observed
synchronous opens are read-only. No application resource factory or migration/
bootstrap work runs. Bound factories throw if inspection invokes them. Real-listener
assertions demonstrate policy denial, CSRF/token/origin denial, executable Zod

core factories are counted and never construct instances. Trusted package imports
must themselves obey the offline contract; this is not a sandbox for malicious JS.
