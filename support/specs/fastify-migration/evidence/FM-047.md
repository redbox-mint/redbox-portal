## Measurement method

The original raw FM-007 archive and all 13 measured harness file hashes were
verified. The client, protocol, proxy and application configuration match the
archived bytes. The [FM-005 workload contract](FM-005.md#fixed-representative-workloads-for-fm-007-and-fm-047)
sets 20 fixed cells, 30 seconds of warmup, 120 seconds of measurement, five
fresh-owner repetitions per cell, 30-second request deadlines and a 60-second
late-completion and queue-drain budget. The timed HTTP load uses direct loopback
and Nginx with `/research`. No browser is involved.

Each sample resets the four Mongo databases, Solr index and attachment volumes.
The workload requires 1,000 measured and 100 separate warmup records, 8 KiB
metadata, strict update preconditions, queued Solr and audit verification, and
content hashes over 1 MiB and 32 MiB attachments. The portal gets 1 CPU and
2 GiB with a 1,024 MiB Node heap. Mongo and Solr each get 0.5 CPU and 1,536 MiB.
Mongo uses a 0.25 GiB WiredTiger cache, Solr a 512 MiB heap. Nginx gets 256 MiB.

The candidate runs its baked `node app.js` command, with the same non-root
benchmark UID/GID (1001:1001) as Express. A read-only preload binds the archived
owner's seed, diagnostics and telemetry to the application returned by the
baked production composition. The preload opens its diagnostic listener after
the real host activates and does not register portal action handlers. The
fixture mounts the FM-044 r4 `redbox-hook-dev` tarball and the two-dependency
FM-007 fixture manifest to select the same storage and demo forms through the
production extension loader. The SHA-256 of the hook tarball is
`70c25fb2a7654f751f8d65271de3732516155911ec5ff5c1a6d6e036daaeaae0`.
The original candidate batches used the baked production logger at `warn`.
The archived Express owner used `nothingLogger`. The logging mismatch affected
W2 and the logging-matched replay supplies its gate results. Baked Angular
assets, the package graph and the kernel revision also differ from FM-007.
[W2 logging review and replay](#w2-logging-review-and-replay)

Latency uses nearest-rank p95 over successful end-to-end completions including
separately counted late successes. Throughput and bytes/s count successes that
completed by the 120-second boundary. Errors, timeouts, late and unaccounted
requests are reported separately. Runs require at least 100 timed successes
and successful persisted-state, drain and cleanup checks. Variability uses
`(max - min) / median × 100` across the five runs per cell. The threshold is
more than 10% slower p95 or more than 10% fewer successful operations/s.

### Remaining threshold breaches

All eight attachment cells and both single-worker page cells remain above 10%
on at least one primary metric. The two candidate batches show the direction
of the remaining gap even where the historical comparison set is noisy. For
example, single-worker proxy 32 MiB p95 was 514.95 ms on r4 and 508.60 ms on
r5, versus 438.47 ms in FM-007. r5 variability was 4.49% for that metric.
The four-worker direct 1 MiB throughput was 62.32 transfers/s with 2.19%
variability, versus 70.22 historically. Retain the 10% gate for these cells.

The r5 page and 1 MiB streaming profiles no longer observed request-path route
name canonicalization. In the page profile, inclusive hotspots were rendering
(21.70%), artifact resolution (18.25%) and EJS (15.08%). Cache validation,
BSON/Prisma decode, and filesystem lookup were also visible. These overlap in
inclusive sampling. The measured profile reproduced the proxy single-worker
page tail at 26.88 ms p95. The profile identifies where r5 spends time. There
is no original Express CPU profile to assign the remaining page gap among
those paths, and single-worker proxy r5 p95 variability is 22.4%.

The single-worker proxy 1 MiB diagnostic matched an attachment pre-validation
guard to all 5,230 request rows. The extra authorization stage took median
0.73 ms and p95 1.80 ms. In that diagnostic the p95 through first byte was
26.08 ms, and measuring each request with its own guard elapsed time subtracted
yielded a p95 of 24.66 ms. This bounds the measured stage cost without removing
any check. The guard cannot explain the entire gap. The Fastify stream path
also observes the source's first chunk or EOF before sending a success body
and joins source/output disposal. Express piped the source straight to its
response. Streaming and persistence show up in the r5 profile, but the test
does not isolate how much of the residual is due to these ownership differences
versus host or library drift. Changes to attachment guard placement or stream
handoff would alter more than declaration lookup and require separate parity
and lifecycle validation. No further minimal fix was verified.

The r5 four-worker proxy 32 MiB profile also found no request-path route-name
work. Native `read` (27.41%), `writev` (17.06%), garbage collection (10.65%) and
`writeBuffer` (8.82%) dominated self time. The profile supports a transfer-path
investigation for the large-stream residual. It cannot assign that residual to
one stream adapter or separate the kernel and proxy effects with this baseline.
