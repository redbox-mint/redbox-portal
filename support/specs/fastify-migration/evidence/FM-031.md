## Production implementation

The production installation binds all **15** original asset declarations:
eight branding deliveries, one branding font delivery, and six dynamic
configuration/template deliveries. `BrandingAssetController` retains the existing
branding mutation actions; `DynamicAssetController` delegates to the same
transport-neutral operation as Express. The original branding operation is moved
to `pages/brandingDelivery.ts`; Express retains its existing export. Delivery uses
the existing administration-invalidated `BrandingDeliveryCache`.

`PortalPages` owns asset/view roots, the logo lifetime, and concrete form,
dashboard, report, template, theme, typeface, disk and repository inputs. No
per-request input is cached. Before-action hook replacements of params, query and
body are read by the selected operation. Typed 400/403/404 failures retain their
identity through the shared page error boundary.

Static delivery runs after declared routes and before unmatched dispatch. It
uses FM-029's `PageArtifacts` containment and specificity rules, ordered installed
roots, `applyPageHeaders`, security/CSP preparation, common conditional freshness,
and the qualified read-stream owner. It does not expose a new filesystem root.
Dot segments, dotfiles, directories, escaped separators, external symlinks,
private files, absent generated files and source paths receive no file bytes.
Files already public in Express, including an explicitly public source map,
retain that exposure. Immutable artifact cookie suppression runs after ordinary
session persistence and also suppresses upstream cookies.

Only an explicitly marked public asset precondition/range refusal retains Accept-Ranges,
Content-Range and Last-Modified through the shared error writer. Other errors
retain the existing header-stripping rules. Capability reply views share the
same response identity for that narrow allowance.

The exact direct dependency `range-parser: 1.2.1` reuses the version already
installed for Express; both lockfile root dependency records are updated. No
package version is upgraded. Production Express disables generated ETags and
installs no outgoing compression; Fastify preserves those behaviors. Theme/font
ETags, Last-Modified, If-Range and supported byte ranges retain their contracts.

### Middleware and route ordering audit

The retained production `PortalHttp.prepare` installs, in order: page headers;
request logging/parsing/session/authentication; installed before-routes
middleware; CSRF and authentication endpoints; root, metadata, pages, APIs and
browser operations; raw/streaming owners; branding/font/dynamic deliveries;
contained static GET/HEAD delivery; installed after-routes fallbacks; final page
not-found policies; and safe error handling. Host admission/readiness precedes
this chain. GET registrations include Express's implicit HEAD unless an explicit
HEAD owner precedes them. Routes registered only for mutation methods can
legitimately fall through to static delivery on GET/HEAD, subject to any other
matching declared GET/all route. A filesystem directory cannot replace the
root redirect.

The native CSRF owner now explicitly registers **GET and HEAD with the same
token/origin/session handler** in `application/portal/host.ts`. This restores its
position before static dispatch for HEAD while keeping automatic HEAD generation
disabled globally. There is no path exception or CSRF-name check in the static
writer. Existing declared/native method matches, once-only hook preparation,
matched `callNotFound` protection and static-before-extension-fallback ordering
remain in force. FM-030 runtime reconciliation now requires both actual CSRF
methods.

`assetRouteCollisions.ts`, called by the existing isolated asset command, derives
concrete targets from **all 335 original FM-002 declarations**. Each target has a
same-named public collision artifact, one at a time to avoid file/directory
conflicts between parent/child routes. `/` is tested with an `index.html`
directory candidate because a root directory cannot itself be a regular file.
Every target is requested through the retained production Express and native
production bootstrap, with the file **absent and present**. GET/HEAD,
origin-form/absolute-form, anonymous/admin/reader actors, `/portal`, an empty
