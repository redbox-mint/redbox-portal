## Production implementation

`http/pageRoutes.ts` and `http/authenticationRoutes.ts` hold the same executable
declarations used by retained Express, inventory generation and native resolution.
Their stable names, URLs, actions, method/HEAD precedence, mandatory browser
policies and CSRF selections are preserved. The complete selected production
installation orders crossed browser/API parameter patterns using the existing
frozen precedence graph, then validates them against the real router.

`http/controllers/BrowserControllers.ts` supplies explicit named actions under the
existing browser controller identities. Existing browser read/write subclasses
retain their exposed actions and concrete inputs; webservice controller identities
stay separate. New named-query/reports page controllers borrow the selected page
owner. Constructors acquire no resources and contain no application/service locator.
`UserController` delegates provider operations to the same native authentication
operations used by the pilot. The production page selection declares authentication
routes rather than separately installing duplicate native routes.

`pages/browser.ts` extracts the retained guarded page action into shared operations
used by both transports. Record access, create permission, form/workflow existence,
dashboard definitions, application configuration and report lookup use the same
domain operations. Native actions pass their operation explicitly. Live request
body/query/params are read after hooks; no request-derived input is memoized.
Missing actor and malformed input checks precede rendering catches, and typed
400/403/404 failures escape generic rendering mapping unchanged.

FM-029's rendering, locals, CSP, page headers, error rendering, redirects,
freshness and HEAD helpers are reused. Authentication JSON uses the existing
serialized-response boundary, and redirects use the existing redirect helper.
The explicit OIDC HEAD denial supplies the retained text representation to that
boundary so content type and GET-equivalent length survive HEAD body suppression.
`PortalPages` owns the merged EJS tree and declares the domain dependencies it
borrows. Lazy concrete input getters remain lazy when browser bindings are added.

## Review round 1 — Express-compatible provider redirects

The reported IPv6 authorization endpoint is reproduced through the retained
Express, shared Express and native production hosts. The previous helper's
`encodeURI` call encoded literal authority brackets as `%5B`/`%5D`, breaking
`https://[2001:db8::1]/authorize`; provider logout and other shared-helper callers
had the same exposure. Shared `responses.ts` now uses **encodeurl 2.0.0**, the
same implementation used by Express's Location writer. The dependency is pinned
exactly in core `package.json` and both consumer lockfiles. It was already
installed transitively: the lockfile changes add only the direct-dependency
metadata line, without a version, integrity or unrelated dependency change.
