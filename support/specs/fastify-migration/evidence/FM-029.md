## Production bindings

- `pages/rendering.ts` owns shared EJS preparation, request-scoped locals, language resolution, translations, navigation, title/layout/partial rendering, CSP nonce creation and negotiated 403/404/500 responses. `PageRequest`, `PageRenderingInput` and `PageResponse` expose plain application facts and operations; no Express request, response, router or handler types appear in these contracts. Express is a thin adapter to this same implementation.
- `pages/headers.ts` extracts the existing cache/Expires/Pragma/COOP behavior without Express types. A missing artifact cannot acquire immutable/public caching merely because its name looks hashed. Static delivery remains FM-031.
- `http/fastify/pages.ts` adapts live native request values after hooks and uses P3's `sendSerializedJson` for bytes, freshness and HEAD, rather than creating a second representation writer. Typed `HttpFailure` preparation/guard errors are rethrown to the sole host boundary; ordinary preparation failures preserve the normal session/error send path and safe diagnostics.
- `PageController` and `PageRootController` borrow concrete rendering/CSRF or root/landing-path inputs. The representative declarations reuse the retained route metadata and mandatory policy order. The root retains ALL dispatch, local-destination validation, 302 negotiation and cache headers, including PROPFIND and HEAD.
- `PortalPages` owns the merged EJS artifact tree through application initialize/close. The production resolved installation binds its lifecycle dependencies before acquisition. Controllers and error callbacks borrow the initialized owner. API2 controller/route replacement still uses normal production discovery and resolution.
- Production host preparation binds global page headers, the existing cookie/session/CSRF owners, authentication error rendering, and a core branded GET/HEAD 404 callback behind reserved namespaces and API2 fallbacks. Typed authorization and brand checks run before page rendering catches. Unknown brand/portal refusals retain their empty body/status framing.
- Deliberate response denials now retain report-only CSP alongside enforcing CSP. The existing redirect helper explicitly sends zero length when Accept selects neither HTML nor plain text, matching retained Express for GET/HEAD.

View selection retains brand/portal candidate specificity before provider-root priority; for the same candidate, explicit deployment roots precede resolved hook/extension roots (highest `hookLoadPriority` first), followed by core views. The existing merged include tree supports includes across roots. Asset lookup for template bundle hashes retains explicit or compiled `.tmp/public` roots, then resolved provider roots, then core assets; this task does not serve those assets.

The canonical source is resolved `server.publicUrl` (including the supported `REDBOX_PUBLIC_URL` environment override). Shared template `appUrl` and `page.origin` use its origin; `page.base`, favicon and redirects use configured root context plus validated brand/portal. Host and forwarded host cannot select those URLs. The retired `sails_appUrl` alias is not reintroduced: the existing strict configuration rejects it. Raw HTTP tests use ephemeral loopback listeners, as P3 does; no manual/browser portal was started.

Compression is intentionally **not enabled**: FM-003 and the retained production host install no outgoing compression. Gzip/Brotli/identity-forbidden negotiation therefore retains uncompressed bytes and no `Vary: Accept-Encoding`. Proxy compression is not qualified here.
