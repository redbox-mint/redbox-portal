### Source and access metadata

`apiRouteRegistrations()` obtains the **152** API declarations from
`registerCoreApiRoutes()`. It does not maintain a handwritten path/action table.
Each view retains the actual `ApiRouteDefinition` object, including Zod request
schemas/extractors, response documentation, security/version metadata and declared
CSRF. No Fastify request schema or response serializer is installed: this does not
move validation ahead of guards, coerce input or strip response fields.

The view uses the existing `resolveEffectivePolicies` and default
`portalHttpPolicies()` configuration, preserving normalized targets and the
most-specific action/controller/global selection. Explicit API `policy` names
precede that selection. Configuration **true** is deliberate public access;
configuration **false** or an absent mapping contributes denial. API declarations
without an explicit `policy` derive their access description from that selected
mapping. A declared policy chain remains the declared access, with additional
configured effects retained separately. In particular **`['nocache', false]`**
remains ordered, rather than collapsing to an immediate deny.

Extension/browser author declarations express public access as
**`{ kind: 'public' }`**, named policies as a non-empty ordered tuple, and denial as
**`{ kind: 'deny' }`**. Empty/malformed named policy declarations and unknown selected
policy names fail offline. Callers supply known bound policy names. The mandatory
installation guard callback is the integration point for FM-016's native policy,
CSRF and validation execution; this task does not implement those security services.

Composition rechecks API method/path/controller/action/declared-CSRF against the
referenced source, and rederives access, effective policies and administration
HEAD rules from the retained configuration. Tests tamper with normalized fields,
policy effects and the source declaration to prove mismatches fail. Request and
response metadata are shared references, rather than copied schemas.

Named replacements require `replaces: true` and an existing target, with complete
new access metadata; duplicate provider names and implicit replacement fail.
Inspection retains each replaced registration, its provider/declaration/API
reference, ordered policy chain, CSRF, paths and previous history. Controller
replacement still belongs to FM-009 and cannot change this route metadata.

### Matching and identity

- Frozen names reproduce FM-002's existing core replacement hash, including its
  two actual adapter rewrites (`:key*` to `*key`, `datastream*` to
  `datastream{*tail}`). The existing Express canonicalizer is used **only for those
  frozen names**, never to decide Fastify collisions.
- Express parsing expands optional groups with a 256-alternative ceiling. The
  translator accepts the concrete inventory's literal/capture grammar and rejects
  unchecked regexes, unsupported wildcard placement, repeated captures and Express
  escapes that would become Fastify grammar.
- Normalized paths share case-insensitive routing, optional trailing slashes,
  significant duplicate slashes, ordinary semicolon handling and the transport's
  existing URL/header bound. Captures retain their case and decode once. Root
  context is prepended once and remains segment-bounded; empty and nonempty roots
  are exercised. Prefixed root aliases preserve Express's zero/one/two trailing
  slash behavior; three trailing slashes miss. Required captures use native
  nonempty regex parameters, allowing lookup to backtrack to a valid wildcard.
  Guards, overlap checks and method lookups see only valid captures.
- Required named wildcards become a string suitable for existing translation
  extraction. The router's stripped trailing slash is restored because it belongs
  to the key. Empty keys miss. Optional datastream suffixes match the bare word,
  concatenated suffix and slash-delimited tails. The ignored tail remains incidental
  input, not a newly defined datastream identifier.
- find-my-way's native `.json`/`.css`/`.woff2` parameter suffix regexes ignore
  `caseSensitive: false`. The translator emits explicit ASCII case-insensitive
  suffix expressions and removes the suffix from the raw capture before decoding
  and guards/actions. Real-router tests include uppercase suffixes and encoded slash,
  newline and percent values.
- A fresh unlistened **Fastify instance** registers every effective method/path.
  `hasRoute`, `route` and `findRoute` perform identity/matching checks against the
  pinned actual find-my-way router. Case, slash, renamed captures, optional
  alternatives, wildcard and method/ALL conflicts fail before controller factories
  or resources are acquired. Native static/parameter/wildcard precedence is tested
  in both declaration orders.
- Inferred HEAD bindings must not bypass an overlapping explicit policy.
  Concrete witness URLs combine the accepted grammar's segment literals,
  parameter suffixes and terminal wildcard prefixes. Separate real routers decide
  whether those witnesses match both handlers; there is no replacement matcher
  deciding collisions. Tests cover crossed parameters, wildcard prefixes and
  suffix combinations. Router registration can also reject an overlap earlier;
  its rejection is authoritative.
- Installation requires `createPortalRouter()` and verifies the host uses the same
  router options, including the bounded query parser, as the offline probe. Every GET
  disables automatic Fastify HEAD generation, and explicit HEAD
  is installed before GET even if the host's global default was left enabled.

### Methods and HEAD ownership

Explicit HEAD retains its own capture names, action and effective policy chain,
independently of declaration/provider order. GET-owned administration HEAD denial
runs the guard callback first, returns **405 / Allow: GET**, and never invokes the
GET action. A differently named HEAD cannot silently erase that denial. OIDC's
separate frozen HEAD identity remains **`core-http-head-e3ee2548904017ea`**;
its action can return 405 without Allow and without invoking GET/provider work.
Implicit HEAD runs the GET guards/action and suppresses the serialized body while
preserving length. The on-send boundary also drains/cancels stream payloads; real
stream ownership and network behavior remain later qualification tasks.

`head: { kind: 'none' }` supports sources without implicit HEAD. Historical health
HEAD reservations are not synthesized into actual health handlers. Exact global
GET health/readiness interception remains FM-011's host responsibility, including
its case/slash exceptions to ordinary routing.

Internal ALL expands to the Node methods accepted by the real router, including
**PROPFIND**, rather than silently narrowing to seven verbs. Explicit OPTIONS/ALL
keeps its guards. Automatic OPTIONS uses a native wildcard fallback so all
explicit OPTIONS/ALL paths take precedence, including paths crossed by a more
specific GET. Actual per-method router lookups accumulate sorted Allow/text;
synthesis bypasses only route guards, adds no CORS permissions and leaves
unmatched paths as 404. Malformed captured URI errors remain safe 400 responses,
including method misses and automatic OPTIONS, matching Express's decoding order.
Shared host stages remain the later host/security composition's responsibility.

The two attachment GET-to-TUS HEAD fallthroughs in FM-002 are not silently flattened
into conflicting handlers. An ALL plus GET collision requires the owning migration
to declare the effective method split/HEAD ownership explicitly. Full browser,
attachment/TUS, provider, static/fallback and extension API2 runtime composition
remain their assigned tasks; this does not mount the 335 legacy handlers or start
mass controller conversion ahead of G2.

## Round-4 wildcard ownership and root audit

Both findings were confirmed against the round-3 artifact on Node 26.12.1.
Protected GET `/x/*tail` followed by public `/x/fixed` or `/x/:id` in legacy
mode selected only the public guard and returned **200** for all **eight**
GET/HEAD/path/root probes. Required `/*tail` returned **200** for bare `/`
under GET and HEAD with a fabricated `tail: "/"`; OPTIONS returned **200 /
Allow: GET, HEAD**. The retained real-Express peer requires **404** for all
three bare-root requests.

The prior audit missed these for specific coverage reasons. The HEAD matrix
ran only `legacyOrder: false`, where differing implicit HEAD policies already
rejected these overlaps. The full inventory table used legacy mode and checked
action identities, but supplied no recording or denying guards; it did not
systematically compose each pair in both orders/modes. Its inventory-derived
wildcard representative had a translation prefix, and the corpus did not lift
that class to required `/*tail` or force bare-root targets for every pattern.
Deleting its final prefixed capture therefore exercised a different native
boundary from bare `/`. Action identity alone also cannot identify a guard that
terminates before action execution. These were missing dimensions, not evidence
that the two reviewed cases were compatible.

Required wildcards now use a native find-my-way constraint registered by the
shared Fastify factory. It distinguishes raw bare `/` from `//` before trailing
slash normalization. A required wildcard cannot win bare-root lookup, so guards,
actions, implicit HEAD and OPTIONS method accumulation all see no wildcard match.
Genuine captured trailing slashes, encoded slash values and optional wildcards
remain supported. Every public `findRoute` probe supplies the same derived
constraint as HTTP lookup; installation, policy overlap and precedence probes
register the same per-pattern constraint. A separate unconstrained native identity
probe still rejects structural duplicates, so constraints cannot conceal a
collision. No request-time route scan or replacement path matcher was added.

Legacy normalization now checks wildcard predecessors and successors using actual
router matches and native precedence. If native selection would change the
source owner and cannot be represented by the existing native exclusions,
composition fails with explicit-ownership diagnostics. Later fallback wildcards
that retain the source owner still compose. The precedence probe distinguishes
wildcard capture values as well as named parameters and static routes.

The expanded retained HEAD matrix adds both composition modes and wildcard/static
overlaps, for **2,016** overlap/order/root/mode cases plus **12** nonoverlap
controls. The differential fixture now records guard declaration identity/count
before any denial or action; every isolated, full-table and pair comparison checks
those guards. Root-level representatives cover all nine classes, and every
pattern corpus includes `/`, `//`, bare prefix and prefix-root targets. The new
pair audit composes every generated crossing from the inventory and root-level
patterns in both orders, modes and roots, comparing real HTTP GET/HEAD/OPTIONS
status, guard ownership, Allow and body, or requiring composition to reject.
The complete inventory still runs together in legacy mode; its unresolved native
composition is explicitly asserted to reject under each root. The source table
now keeps GET-owned HEAD implicit. Legacy composition inserts that binding beside
its GET in source order, before subsequent ALL bindings; actual separately
declared HEAD policies are registered first, so legacy exclusions cannot assign
an ALL-owned URL ahead of an explicit HEAD guard.

The first expanded run found two additional divergences: legacy ALL-owned HEAD
could bypass a separately declared HEAD (24 matrix cases), and literal `/`
overlaps required root wildcard at `//` (four pair-mode/root cases). Composition
now registers explicit HEAD policies before ALL bindings in legacy mode too and
rejects any precedence change that native exclusions cannot preserve. Overlap
witnesses include optional trailing-slash forms and the real routers decide
whether they intersect; this catches root/wildcard guard conflicts while keeping
bare `/` distinct from a genuine slash capture.

The final HEAD audit result is **1,732 rejected / 284 matching Express guards**
across all **2,016** cases, plus **12** nonoverlap controls. The GET/GET portion of the pair audit covers
**759** pattern pairs and **421** generated targets, including every original
full-inventory crossing. Both declaration orders, both modes and both roots give
**6,072** composition cases: **3,980 rejected / 2,092 accepted**, with **18,828**
real-HTTP GET/HEAD/OPTIONS comparisons for accepted compositions. The same pairs
also run as GET/OPTIONS combinations in the final audit. Combined, the audit
executes **12,144** composition cases: **3,980 rejected / 8,164 accepted**,
with **73,908** real-HTTP comparisons. Per-pattern **27,454**, full-table
**195,822** and pair **73,908** comparisons total **297,184** in each complete run. Each guard
comparison records the selected declaration before action execution, including
responses ended by a denial.

A further real-HTTP root/method probe found that constrained explicit
`OPTIONS /*tail` hid synthesized OPTIONS for GET `/`: Express returned **200 /
Allow: GET, HEAD**, while Fastify returned **404**; both correctly ran the
explicit guard and returned **403** at `//`. The actual router now retains an
unconstrained automatic OPTIONS fallback alongside a constrained explicit wildcard.
Native constraint selection gives the explicit guard priority for genuine captures;
only native misses reach synthesis. Source-source structural collisions still
fail against the independent native identity probe. Four root/mode regressions
and GET/OPTIONS as a method axis for every generated pair retain this check.

## Round-5 generic access-overlap rule

The round-5 findings were reproduced on the preceding artifact under Node
26.12.1. POST/PUT/PATCH/DELETE wildcard/static crossings returned **200 through
only the public guard** in native mode under both roots (eight probes).
OPTIONS-only `/submit/:id` returned **404** for malformed GET/HEAD captures in
both modes and roots (eight probes). Express's retained differential fixtures
supply the required 403 and 400 oracles respectively.

The HEAD-specific overlap validator and its separate explicit/inferred/denied
HEAD passes have been deleted. `composeRoutes` now expands the complete binding
set first: ordinary methods, every Node-supported ALL method, implicit HEAD and
GET-owned HEAD denials. **Every same-method pair that actual find-my-way probes
match at a generated overlap witness must have equal effective policies (including
order and false), public/access kind, CSRF flag and selected CSRF adapter,
executable validation declaration, and any HEAD-denial effect. Otherwise
composition fails unless an explicit precedence declaration names the winner,
other stable identity, override name and nonempty reason.** This runs before
implicit HEAD deduplication or legacy exclusions can hide a binding. No method or
HEAD binding kind receives a guard-overlap exemption.

Validation uses original executable declaration identity, including browser and
integration request declarations; JSON serialization of a Zod schema or extractor
cannot prove equivalence. Selected legacy CSRF adapter metadata is retained beside
the original flag. This intentionally treats unknown/different executable
validation declarations conservatively. Identical metadata still undergoes
native structural collision and legacy ownership checks.

Precedence declarations must identify existing, distinct routes, use valid
methods, have unique names and be used by a real overlap. Conflicting declarations
fail. Each accepted declaration is then checked with a native router containing
the effective paths: it must actually retain its named winner. Merely supplying
a reason cannot authorize an implementation that selects the other guard.
Express's deferred automatic OPTIONS has its own inspected, named precedence
against each explicit OPTIONS/ALL owner and its own public metadata.

Offline probes now use **find-my-way 9.10.0** directly, with the same shared
options and native nonempty-path constraint as Fastify **5.12.8**. A retained test
asserts both resolve the _same installed module_. This removes full Fastify probe
instances and parameter-name inference of the winning handler: native `store`
identity identifies the selected binding. The existing transitive router is
promoted to an exact direct core dependency; the core manifest and both lockfiles
change by one dependency entry each, with no version upgrade.

Malformed-capture validation is separate from Allow accumulation. All real
method matches, including explicit OPTIONS, participate in decoding validation.
Native binding identity excludes the automatic OPTIONS fallback; only Allow
collection filters out OPTIONS. OPTIONS-only regressions exercise malformed,
valid and encoded-slash captures on GET/HEAD misses in both modes and roots, and
unknown malformed URLs verify that the synthetic fallback cannot create a 400.
