## Multipart, concurrency and lifecycle

The existing `StreamingMultipart` and storage owners retain parsing, limits,
staging/finalization, cleanup retries, quiesce and drain. Fastify scopes its raw
multipart handoff to resolved multipart bindings. JSON/form/bodyless behavior
outside those media types remains under the existing parser/security order;
there is no global stream-consuming upload parser. All fields are available
before hooks, including fields after a file. The native staging lease remains
owned through action completion, early hook replies/errors, cancellation and
cleanup failure. `onSend` joins cleanup before publishing a normal response.

Datastream actions read live request input again after `beforeAction`, including
query/param/header concurrency input. Branding actions revalidate the live body
and expected draft revision after hooks. No request-derived action input is
memoized. For datastream uploads, host declaration extraction/validation is not repeated
by the action; the action rereads live domain values. Branding retains host
validation before hooks and validates live domain fields again in its action. The existing authoritative save-request header and `If-Match`
semantics are preserved; extra multipart save/version fields retain their
Express pass-through behavior. Real WOFF2 upload tests prove that the multipart
`expectedDraftRevision` field works before and after the file and stale revisions
return branding conflict without staged residue.

TUS retains the pinned server/datastore and its per-upload lock, state metadata,
chunk staging, finalization, actor/brand/record binding, size limit, disk reserve
check, termination rules and safe error bodies. Location is a relative URL built
from configured root context and the parsed request pathname. Host,
X-Forwarded-Host and absolute-form authority cannot select its origin. Allowed
Origin comes from the configured canonical public URL. Creation, HEAD, PATCH,
concurrent offset conflict, deferred length, creation-with-upload and termination
use the same protocol owner as Express. Default expiry remains disabled, as in
Express (`expirationPeriod=0`); no expiry policy is invented.

Cancellation removes multipart staging after the provider actually settles.
TUS cancellation intentionally retains the successfully received offset and
resumable part: a cancelled 256 KiB PATCH after 64 KiB yields offset 65536, then
resumes to exact complete bytes with no abandoned parts. Provider failures keep
resumable state and a safe response. Stop retains accepted protocol, provider,
cleanup and audit work before persistence pools close; a deadline can be retried.

A native-only terminal-publication adapter handles the pinned srvx bodyless
response path calling `end(callback)` after the raw response has been destroyed.
Node does not invoke that callback in this case. The adapter settles that end
callback once on destruction/close, restores the original method/listeners, and
still awaits the TUS handler/provider and audit. It does not race the protocol
handler against socket close or release unfinished provider work.

## Raw session and error audit

TUS commits the prepared native session before hijack or raw headers, copies
prepared headers/cookies, and links the actual raw request lifetime. Session
storage failure produces a safe ordinary 500 before TUS state or cookies are
published. Tests hold the real store CAS to prove no early headers, successful
persistence of a session mutation, and safe failure with no state. The existing
Companion session handoff alias remains available; Companion transfer behavior
is outside this task.

Shared actor/admin/record-brand/edit guards precede generic upload error mapping.
Reduced-policy, missing-actor, typed missing-record and live-hook replacement
cases assert refusals before storage/state acquisition. Browser uploads retain
CSRF behavior, including TUS HEAD and all three branding browser routes. API
bearer requests retain canonical Origin enforcement.
