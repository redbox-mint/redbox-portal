Core and installed API registrations retain the same configuration identity. No change was made to the policy resolver, default deny behavior, explicit API source checks or route precedence verification.

The packed extension adds ProbeController/read. A real HTTP production-factory regression first allows GET/HEAD, then selects `{ '*': true, ProbeController: { read: false } }` and verifies both return 403. The selected effective chain is `['nocache', false]`: no-cache executes before denial, and the beforeAction hook/action do not run. The explicit probe policy is the API source of its declared access; the catalogue API now also declares its existing access chain explicitly. API source mismatches still fail offline.

Final pilot qualification additionally exposed a repeated-brand-policy error: explicit API policies precede configured policies, so the same built-in policy can legitimately appear twice. Native branding now remembers its own prior successful resolution, accepts only the same brand ID/portal, preserves the frozen tenant snapshot, clears the previous actor so configured authorization refreshes it as Express does, and rejects conflicting selections. The private context setter still rejects a second write. Four real HTTP Express/native credential cases, a context-conflict regression and a real HTTP role-change regression cover this; every other policy still executes in its original order.

Production call sites use exported, stricter `Production*` option types with `satisfies`. They require every option, preserving the optional low-level fixture APIs. Policy configuration, provider priority, module names, namespace configuration and proxy trust cannot be omitted on the production path. Disabled observation/context callbacks are explicit undefined selections; parser exclusions explicitly select an empty list because no raw integration belongs to this pilot. The native host receives explicit listener, owner, logger, registry, namespace and security selections. The shared logger helper retains the exact prior owner-logger behavior.

Resolved module names are computed/frozen once in API2 resolution and shared by identity with controller composition and the host. Configured Companion route/server paths explicitly select namespace reservations, including when its transport is disabled. Production host composition consumes the immutable resolved installation without re-resolution or re-composition.

`productionCompositionInputs.ts` spies the actual packed production bootstrap, loader, resolver, compositions, native host and security preparation. Non-default configuration and real requests exercise the installed module, replacement, policy denial, hook and fallback. Each object-options assertion enumerates `Record<keyof UnderlyingOptions, Check>`; positional options use required parameter tuples. Adding an optional underlying input therefore fails the qualification typecheck until the audit includes it. Every resolved-installation field is checked against its original resolution/selection, including non-HTTP contributions. Strict installed-consumer compilation rejects omissions of each of the four unsafe selections and verifies the named missing-property diagnostics. The consumer AST guard rejects erasure casts and TS suppression comments in these negative programs too.
