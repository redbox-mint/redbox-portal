## Implementation

Both transports delegate to named actions in `http/actions/identityAdministration`,
`identityLinks` and `administration`. The extraction retains target/brand/shared
account checks, linked-primary and disabled-account rules, role assignment and
partial-commit behavior, audit calls and safe per-family failures. Explicit native
factories expose only the selected actions. Concrete lazy bindings in
`application/portal/identityHttpPlan` borrow the same production domain owners as
Express, without acquiring resources during offline installation.

Shared actor preludes run before declared validation on both hosts. The host
also invokes those same guards before extension actions, preserving policy/CSRF
precedence and reduced-policy missing-actor handling. Existing `readAction`,
`executeReferenceRead`, non-coercing version extraction, freshness, submitted/deny
helpers and one guarded JSON encoding are reused. No Express bridge, duplicate
authentication/CSRF stack or hand-built action dispatcher was added.

Production declaration selection preserves policy chains and browser/API CSRF
modes, including the safe-method refresh route's explicit mode and admin HEAD
405 behavior. Session authentication remains permitted by retained API behavior
with the required CSRF token. Explicit bearer credentials retain precedence over
browser sessions, never acquire session roles and never create a browser login.
Browser AJAX writes continue to require CSRF even with a valid bearer.

The existing branding CSS/font cache maps and invalidation are extracted into
an application-local `BrandingDeliveryCache`. Express delivery uses the same
implementation; native administration invalidates the installation-owned cache
without constructing an Express asset layer. Native page/asset publication remains
later work. Scoped HTTPS and empty-denial headers preserve production framing:
an empty end while session save/touch is pending is chunked, while an untouched
fresh session ends with `Content-Length: 0`.

and host-specific session documents are restored before each independent case;
a stale-actor request cannot invalidate the next case's positive control.

through real Mongo. Successful writes must create both user-audit and security
rows. Every row is compared, including record and record-audit mutations, and
synthetic passwords, SIEM secrets and injected backend messages are checked for
redaction. Only volatile timestamps/identifiers, generated credentials, cookie
values and collector origins are normalized.

Stateful flows additionally verify token rotation/revocation against subsequent
API authentication while the browser login remains usable, and account linking
with a real record ACL rewrite, link/audit reads, alias-management refusal,
primary disable/effective-alias state and re-enable. A real local SIEM HTTP sink
returns a synthetic secret/backend marker to exercise response/event redaction.

## Pre-existing issues (deferred)

`'true'`. Thus `GET /portal/default/rdmp/api/users?includeDisabled=true` still

controller code uses `=== true`, so the report deliberately does not claim that
older layout has the same defect. Fixing retained behavior is unnecessary for
this migration and would break its required parity, so it remains deferred under
the common brief's retained-Express policy.
