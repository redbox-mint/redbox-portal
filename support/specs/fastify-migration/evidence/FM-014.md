## Native boundary and ownership

`prepareNativeSessions` inspects the configured collection through existing
`prepareSessionIndexes(..., 'inspect')`; missing/conflicting TTL indexes fail
before listening. Only explicit `persistence:indexes` / `ensure` maintenance
creates `expires_1` with `expireAfterSeconds: 0`. Existing collation validation is
retained. The store creates no client, pool, index, timer or background task.

The store borrows the application-owned `mongoSessionDatabase(owner, config)`
collection. Database/collection overrides reuse the pool for matching connection
policy. Its registered `sessions` resource drains every operation/callback before
application cleanup releases that pool. Store close only fences references and
disables its request-local inflation context; it never closes the client.

Every get/set/compareAndSet/touch/destroy requires an active owned HTTP request,
retains its promise/callback through FM-012 lifetime, and participates in resource
drain. Accepted operations continue through disconnect, quiesce, stop deadline and
retry. Stale/unowned calls fail before I/O. Session callback-returned promises are
also retained through the capability view.

New sessions insert. Existing saves atomically match version and generation,
without upsert; stale saves after logout/rotation cannot resurrect the old key.
Admission checks document expiry. An admitted request may save/touch after that
expiry, matching Express while generation/deletion still enforces revocation.
Touch changes only expires/optional lastModified, preserving concurrent payload
mutations. ENOENT revokes the affected Session reference and prevents an explicit
stale-save error response from issuing credentials or starting another write.
Other database failures remain retryable; public errors disclose no Mongo detail.

## Express compatibility and review corrections

The baseline is the actual current `composeHttpSession` + connect-mongo, including
application-owned client facade, `autoRemove: 'disabled'`, collectionName mapping
and explicit TTL maintenance. Its configured secure:false becomes **auto**.

Retained behavior includes signed/URL-encoded redbox.sid, configurable name,
path/domain, HttpOnly, SameSite, partitioned, priority, secure/auto/proxy handling,
millisecond maxAge, rolling/resave/saveUninitialized defaults, fallback TTL
1,209,600 seconds, ttl/touchAfter, and storage even when Secure emission is
suppressed. Unmodified anonymous requests create no state/cookie unless required
by saveUninitialized. Undefined defaults remain Secure/HttpOnly/Lax.

Round-1 review regressions remain in the differential:

1. Lookup reconciles native admission with the authoritative document expiry.
   Mongo touch intentionally leaves serialized cookie expiry unchanged; renewed
   document expiry admits reads past original maxAge without regenerating data.
2. Every replacement Session receives normalized Secure/SameSite before caller
   continuation, persistence or emission, including first-request regeneration.
3. Trusted X-Forwarded-Proto uses the **first** entry. Session proxy:false ignores
   forwarding; proxy:true lowercases/trusts it; inherited host trust checks the
   immediate peer and preserves Express protocol case. Host trust includes CIDRs.
4. Request-entry data/identity and attempted-save hashes separate modification,
   persistence and renewal. With default touchAfter:0, unchanged explicit saves or
   resave:true requests do not renew a rolling:false cookie; modification still
   does, including after explicit save.

Round-2 corrections:

1. **Expires-only lifetime:** the transport-local SessionCookie derives
   originalMaxAge from expires exactly as Express does. Both orders of expires
   and maxAge retain insertion-order precedence. Zero/negative ages and session
   cookies are included. Rolling expires-only reads retain data at +750/+1,500ms.
2. **Save retry:** ordinary failed saves do not poison Session references.
   Attempted-save state follows Express retry decisions. An explicit successful
   retry persists and emits the proper cookie. Automatic persistence failures
   latch request-local suppression against implicit error-response retries.
3. **Cookie option preservation:** SessionCookie inflation/replacement and
   emission retain all fields forwarded by Express Cookie.data, including
   Partitioned and Priority. The cookie encoder option is accepted by Cookie but
   excluded from Cookie.data in actual express-session; a throwing custom encoder
   proves neither stack invokes it. No Express runtime is imported by native code.
4. **Reload expiry:** request-local AsyncLocalStorage preserves serialized cookie
   expiry/originalMaxAge through both entry lookup and reload. A reload/save at
   +250ms stores the original +1,200ms expiry; response touch happens separately.

Round-3 corrections:

1. **Returned method ownership:** the generic FM-012 public view recognizes a
   framework method returned by any accessor and reuses its canonical guarded
   method. This includes get, property/Reflect reads, descriptors, destructuring,
   getter aliases and spread. All four asynchronous Session methods
   (save/reload/regenerate/destroy) retain callback-returned work through shutdown.
   The 36 new real-Mongo regressions end the HTTP response while the callback is
   blocked, prove stop times out without closing the borrowed client, then release
   the callback and prove a stop retry closes exactly once.
2. **Option-update state/order:** options mutates the existing cookie with only
   the supplied fields in insertion order, matching Express cookie assignment.
   Attribute-only updates retain cookie identity, expiry and originalMaxAge; both
   orders of supplied maxAge/expires retain caller precedence. New delayed chains
   act at +50 seconds on session/maxAge/expires cookies, including 60-second
   lifetimes, and read through +61.5 seconds.
3. **Original request targets:** session admission uses shared requestPathname,
   preserving raw escapes and Express literal cookie-path prefix matching. The
   qualified native synchronous path check sees the admitted cookie path; raw.url
   is restored before caller continuation and throughout asynchronous store I/O.
   Absolute HTTP targets persist through .set(), and application code sees the
   exact original target. Outside-path requests expose no Session, matching
   Express rather than the native empty-object placeholder. The target grid also
   found native slash-boundary matching differed for /scop versus /scope; literal
   prefix admission fixes that retained case without changing the router.

## Forced-login and rollback decision (design §9)

- Native keys use `redbox-fastify-v1:` and document version 1. Express unprefixed
  keys remain unreadable. The existing expires_1 maintenance covers both formats.
- HMAC-SHA256 derives host-specific signing keys from each configured root and the
  namespace. Reusing a development root still cannot accept Express signatures.
  Native metadata supplies generation checks; prior authenticationVersion payload
  is not promoted to a native authenticated session during cutover.
- Deployment **must provision a fresh random root at cutover and again on rollback,
  without retaining a preceding-host root in the verifier set**. Rollback rejects
  both old Express and native cookies, including clients that never visited the
  new host, so intervening logout/revocation cannot silently revive old login.
- Within a native deployment, roots of at least 32 characters allow ordinary key
  rotation (first signs, remaining keys verify). Production schema still supplies
  one string. A real Express listener with a new rollback root and populated old
  MemoryStore rejects both old cookie formats.

Deployment enforcement/authenticated rollback rehearsal remains FM-019/049/050.
