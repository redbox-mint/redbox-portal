## Production change and ownership

All six original declarations now select real production Fastify actions: API
attachment listing/download, browser attachment listing, ordinary and Companion
attachment download aliases, and generic browser datastream download. Declaration
identities, policies, CSRF, API schemas and explicit HEAD behavior are retained.
The declarations have a neutral home (`http/datastreamRoutes.ts`); Express keeps
its original export. Both transports delegate to `http/actions/datastreamReads.ts`
for actor, record-brand/view permission, membership, safe error, filename and
storage acquisition logic. Native controller inputs are explicitly bound through
the production installation and read/mutation/browser controller factories.
The host repeats the shared actor/record/identifier prelude before declared
validation; the action reads live input again after hooks. No request-derived
result is cached. Denied/missing membership never opens a producer.

Fastify hands every stream to the **existing single `sendReadStream` helper**.
It owns response delivery, bounded backpressure, cancellation and awaiting source
disposal. Storage owns its concrete resource cleanup: GridFS retains its cursor
close promise through the persistence resource drain; filesystem `_destroy`
closes its file. There is no second native pipeline or response stream owner.
Download headers enter inside that retained helper, so a header/handoff failure
cannot abandon the acquired stream. Buffered storage results use ordinary bytes.

The two `.../record/:oid/attach/:attachId` GET aliases deliberately retain their
original HEAD fallthrough: policies run, then the separately owned **FM-034 TUS
HEAD** handles the request. Permitted native TUS HEAD remains safe 501 pending
FM-034. API/generic downloads and listings implement ordinary HEAD. This does
not leave an FM-033 placeholder: every FM-033 GET owner is selected and real.
The ownership table preserves the HEAD guard before that protocol fallthrough.

## Retained wire behavior and accepted stream semantics

Retained Express is loaded from the immutable starting SHA, transpiled into a
removed temporary directory, and installed only during the production Express
preparation. The comparison runs retained Express, shared-action Express and
production Fastify through their actual application/installation/host bootstrap,
using raw `node:http` sockets, never injection or a hand-built portal. Only Date
is frozen. The retained adapter SHA-256 is
`7f9b5989265e0597aa506240aa87788c77883f672d6782e5c268c6ea18e02960`. Connection/request IDs and independently generated session/CSP values
are normalized where applicable; representation headers and bytes are compared.

* Express streams these downloads directly and **ignores Range and If-Range**,
  including multi-range and unsatisfiable requests. The complete object remains
  status 200. Fastify preserves this supported baseline, with no invented 206/416
  or multipart-range behavior.
* File responses expose **no ETag, Last-Modified, Accept-Ranges or Content-Range**.
  Conditional requests retain the existing freshness behavior. Listing JSON
  responses retain shared conditional handling.
* MIME type follows Express `attachment()` filename extension/basename behavior;
  RFC UTF-8 Content-Disposition and fallback filename bytes match. Known metadata
  lengths are retained. Normal real GridFS attachment listings omit `size`, so
  their file responses are chunked. Successful page-policy downloads retain
  `no-store, no-cache, must-revalidate, proxy-revalidate` plus existing headers.
* The inherited user-approved STREAM decision applies: **pre-first-byte error →
  safe complete 500 for GET and HEAD; post-commit error → abort; post-EOF disposal
  error → log once, complete response stands, shutdown still awaits disposal**.
  HEAD consumes the same source and carries GET's representation headers without
  a body. This includes GET framing for an unknown-size stream, zero for an empty
  stream, and the actual Content-Length for a buffered storage result, where
  preceding Express HEAD omits that implicit framing. The initial matrix accepts no other response deviation; upstream 204 framework
  behavior observed in review round 1 is recorded separately below. Mid-stream storage errors use redacted `HTTP_STREAM_FAILED` once.
